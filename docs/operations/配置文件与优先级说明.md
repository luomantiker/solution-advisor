# 配置文件与优先级说明

本系统将“部署可配置项”和“版本化平台资产”分开。部署人员通常只需维护下列四类配置；所有
Secret 均只保留在部署或 Agent 主机，绝不提交 Git。

| 配置文件 | 维护位置与权限 | 用途 | 何时修改 |
|---|---|---|---|
| `.env.example` | 开发工作副本 | SQLite、本地文件、Redis、上传上限等开发运行参数 | 本地开发环境变化时 |
| `.env.production` | 生产部署主机，建议 `0600` | PostgreSQL、MinIO、Redis、身份方式、上传限制和内部 Worker 注册 | 首次部署、基础设施或身份方案变更时 |
| `/etc/solution-advisor/host_agent/config.yaml` | 每台通用 HostAgent 主机，由安装器维护，建议 `0640` | Agent 实例 ID、控制面地址、只读镜像发现、能力与注册 Token 路径 | 安装/升级 HostAgent 时 |
| `/etc/solution-advisor/workers/<实例>/config.yaml` | 使用 X5 直连 Worker 模板的 Host，建议 `0600` | 受控 X5 包、并发、Evidence 类型和板端 Profile 路径 | 调整该 X5 Worker 实例时 |
| `/etc/solution-advisor/workers/<实例>/board.yaml` | 仅带真实板卡的 Host，必须 `0600` | 板端地址、账户、已知主机、远端受控目录、密码文件路径 | 板卡或账户变化时 |

`registration-token` 与 `board-ssh-password` 是上述 YAML 所引用的独立 Secret 文件，不是可提交的
配置样例。通用 HostAgent 的 Token 为 `/etc/solution-advisor/host_agent/registration-token`；X5 模板的
路径由其 `registration_token_file` 指定。Agent 安装、升级与 systemd 路径见
[HostAgent 安装与升级](HostAgent安装与升级.md)。

## 优先级

### API、migrate、common-analyzer

运行时的值按低到高覆盖：

```text
代码默认值（Settings.from_env）
  → .env.example 或 .env.production（Compose env_file）
  → docker-compose*.yml 中某服务的 environment
```

开发 Compose 为避免误用生产身份，会在 `environment` 强制设置 Redis 地址和测试身份；这会覆盖
`.env.example` 的同名项。生产 Compose 只读取 `.env.production`，应把生产值集中保存在该文件。
修改环境变量后需重建相关服务，例如：

```bash
docker compose -f docker-compose.prod.yml up --build -d
```

### 登录方式

本地账号和企业 SSO 是独立、可同时启用的身份来源，登录成功后都映射到同一个 `users` 表并由后端
读取三角色（普通用户、管理员、超级管理员）。JWT 内携带的角色不参与授权。

| 登录方式 | 显示条件 | 必需配置 |
|---|---|---|
| 内建本地账号 | 存在 `LOCAL_AUTH_HMAC_KEY` | 已初始化的本地人员；首个超级管理员仅能通过受保护的一次性部署初始化创建 |
| 企业 SSO | `SOLUTION_ADVISOR_ENTERPRISE_SSO_ENABLED=true` 且 issuer/audience/HMAC 均完整 | `IDENTITY_ISSUER`、`IDENTITY_AUDIENCE`、`IDENTITY_HMAC_KEY` |

未满足显示条件时，网页不会显示对应入口，后端也会 fail-closed 拒绝该来源。当前 `.env.production`
本地人员由超级管理员在“人员管理”中创建、停用和重置初始密码。首次超级管理员只允许在空库部署时通过
`SOLUTION_ADVISOR_LOCAL_BOOTSTRAP_ENABLED=true`、`SOLUTION_ADVISOR_LOCAL_BOOTSTRAP_LOGIN` 与私有密码环境变量
一次性初始化；系统发现已有超级管理员后不会再次读取或覆盖该密码。公司 SSO 准备好后再将企业 SSO 开关置为
`true` 并填写三项 JWT 配置。
模板中的 OIDC/SAML/JIT 段目前只是完整配置预留，必须维持关闭，不能误认为已经具备重定向登录或
按群组自动开户能力。

### HostAgent 与板端

Agent 的实际授权优先级为：控制面已发布 Catalog/Binding/任务租约最高；实例 YAML 只能提供该 Host
的固定运行事实；板端 Profile 只补充连接信息；Token 和密码文件只提供凭据。页面、Candidate、模型
或 Agent 请求都不能注入 Shell、Docker 参数、路径或凭据。

`platform_packages/x5/manifest.yaml`、`rules/rules.yaml`、`docker/image.lock.yaml` 是随平台包版本审核和
发布的不可变资产；它们不是部署人员应在生产现场临时修改的用户配置。`docker-compose.yml`、
`docker-compose.prod.yml` 是服务拓扑编排；通常选择其一运行，而非把秘密直接写进 Compose 文件。

## 修改前检查

1. 先确定业务域：基础设施、对象存储、身份、Agent 或板端；不要跨段复制相似变量。
2. Secret 仅写到 `.env.production` 或 Agent 受保护文件，模板只保留 `change-me` 占位符。
3. 修改生产 `.env.production` 后执行 Compose 配置校验和重建；修改 Agent YAML 后通过安装/升级工具重启服务。
4. 不要修改平台包镜像锁、规则或 Catalog 来临时绕过受控执行边界。
