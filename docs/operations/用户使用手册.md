# Solution Advisor 用户使用手册

Solution Advisor 用于在已纳管的平台上，对 ONNX 模型执行受控评测。系统把模型分析、平台编译、板端性能测量、评测依据、网页报告和 PDF 串成一条可追溯的评估流程（Flow）。

本手册面向普通用户、管理员和超级管理员。平台真实运行必须由固定 Runner 和 HostAgent 执行；页面不会也不应接受 Shell 命令、Docker 参数、板端地址、路径或密码。

## 1. 登录与首页

访问部署管理员提供的站点后，会先进入独立登录门户：

- **本地账号登录**：输入人员管理中创建的账号和密码。新建账号默认直接启用，默认初始密码为 `Realthon_1`；登录后可在右上角“修改密码”自行更改。
- **企业 SSO 登录**：仅在组织启用并完成配置时显示。SSO 只负责识别身份，系统角色仍以后端账号库为准。
- **登录后首页**：展示本人正在进行的评估、已完成评估、模型数量和可下载报告。左侧“通知消息”可按评估、平台和账号维度筛选，并支持单条删除、全部已读和清空显示列表；清空通知不会删除业务数据或审计。

普通用户仅能看见自己的模型、评估、报告和被明确共享的资源。管理员/超级管理员看见的平台治理入口由后端授权决定，不能通过修改网页绕过。

## 2. 上传模型与通用 ONNX 结构分析

在“模型评估”页点击“上传模型”，选择 ONNX 文件后等待分析完成。上传完成不等于平台评测完成；它首先建立模型资产和通用 ONNX 分析快照。

模型详情会展示：

- 文件名、文件大小、格式、SHA256 文件标识、上传时间与访问范围；
- ONNX IR、opset、节点数量、算子类别和算子统计；
- 动态 Shape、控制流算子、外部权重等基础检查；
- 管理员在系统设置中按模块启用的扩展检查结果（未启用的项目不会伪装成“已通过”）。

分析成功表示文件可被当前通用分析器读取并得到结构快照，不表示任何具体平台一定支持，也不表示精度、稳定性、功耗或部署推荐已经验证。

## 3. 创建一次评估

在模型详情点击“创建评估”。创建向导分三步：

1. **确认模型**：核对模型名称、大小、算子统计、ONNX IR/opset 与分析状态。
2. **选择对比平台**：只能选择已发布 Catalog 且同时具备健康 Binding、在线 HostAgent、READY Worker、匹配 Runner 和所需能力的平台。同一平台类型的多个版本按页面规则选择其中一个版本。
3. **核对提交**：确认模型、平台和受控预设。提交时后端会原子检查所有已选平台；任一个不可调度都会整体拒绝并说明中文原因，不会创建半套流程。

用户只看到一条 Flow。系统内部为每个平台建立独立的编译阶段和板端性能阶段：编译可受平台容量并行执行；同一 Binding 的板端阶段互斥串行，避免同一板卡争用；不同 Binding 可并行。一个平台失败不会覆盖另一个平台的真实结果。

## 4. 查看 Flow、结果与评测依据

在首页的“最近评估”、模型详情的“历史评估与报告”或“评估报告”进入 Flow。

Flow 详情包含：

- 总体状态：等待、执行中、成功、部分成功、失败、取消或超时；
- 按平台横向分组的阶段时间线：编译成功后才会进入该平台板端性能阶段；
- 平台结果：模型格式、测试执行器、结果解析器和固定条件下的实测结果，例如平均延迟（ms）；
- 评测过程依据与制品：按平台分栏。左侧彩色竖条表示产生方式——蓝色为工具链原生输出、绿色为平台评测脚本输出；下载时服务端再次校验权限与归属；
- 冻结快照：本次 Flow 创建时锁定的平台版本、Runner、规则、解析器和模型分析。页面不会混入 Candidate、管理员验证、其他 Flow 或 DEMO 的数据。

“成功”仅说明该平台这一次冻结条件下的末阶段成功。若输入、线程、帧数或 Runtime 条件未对齐，不应将不同平台的性能做无条件排名。页面明确列出未验证的输出一致性、精度、稳定性、功耗和部署推荐。

## 5. 网页报告、PDF 和历史版本

终态 Flow 可打开“查看评估报告”。网页报告和 PDF 是同一份 Flow 事实的不同展现；PDF 首次下载时生成并持久化，之后可直接下载已有版本。报告会包含：

1. 多平台结论摘要、工具链版本、编译结果与可用的实测延迟；
2. 通用 ONNX 模型检测关键属性与扩展检查结果；
3. 各平台适配与板端测试事实；
4. 后续优化建议及明确的未验证边界。

报告版本是可审计历史。拥有者、管理员和超级管理员可删除指定历史报告版本及其仅被该版本引用的制品；删除会有明显确认框并记录操作人、事件和行为。删除不推荐，且不会删除其他 Flow 或共享引用的对象。

## 6. 模型、Flow 和报告的删除

- **删除 Flow/历史评估**：只在全部内部阶段已结束时允许。会清理该 Flow 的阶段任务、结果、仅被它引用的 Evidence/Artifact 和对应报告，但不会删除原 ONNX、其他 Flow 或平台治理数据。
- **删除模型**：由超级管理员在“系统设置”开启全局开关后才显示。删除会同时删除该模型相关评测内容，因此页面会明确警告。若同一 ONNX 文件仍被其他用户引用，底层文件会保留，直到引用数为零。
- **删除报告版本**：见上一节，只删除指定版本及仅该版本引用的制品。

运行中的评估不能删除；请等待终态，或由具备权限的人员按实际流程取消。

## 7. 平台管理（管理员）

平台管理采用三态工作台：**可接平台候选项 → 候选平台 → 可用平台**。

1. HostAgent 只读发现镜像；管理员可在“可接平台候选项”创建 Candidate 或忽略/隐藏无效镜像。
2. Candidate 同一时刻只允许一位管理员人工认领。认领人登记平台资料与固定规则，进行离线契约检查和真实接入验证；其他管理员只读。
3. 认领人可主动释放。超级管理员可带原因强制释放，或先清理后指定新的 ACTIVE 管理员。释放或指定都会清理本次接入资料，绝不会把进行中的资料直接交给下一人。
4. 当前修订通过真实验证、Package 与 Evidence 齐全后，管理员审核发布不可变 Catalog；再由目标 Host 创建健康 Binding 与 READY Worker。
5. “系统设置 → 平台配置备份与恢复”供管理员和超级管理员使用，可备份已发布平台的受控定义 ZIP，并在新部署恢复后安装对应 Runner、建立 Binding/Worker。备份包不含 Host、Worker、用户、模型、Evidence 二进制或秘密。

Candidate 不使用倒计时、自然超时或自动释放；以人工认领、主动释放和超级管理员受控处置为准。

## 8. 人员管理（管理员/超级管理员）

人员来源有四类：

| 来源 | 含义 |
| --- | --- |
| 系统内建 | 系统初始化保留账号，例如超级管理员 |
| 内部生成 | 管理员或超级管理员手动创建、且非测试标记的账号 |
| 测试专用 | 自动化、验收或人工创建时明确标记为测试的账号 |
| 用户注册 | 为未来自主注册预留；当前未启用 |

人员列表支持按来源、角色、启用状态和名称/账号筛选，并可选择每页 10、20 或 50 条。管理员只能管理普通用户；超级管理员可以管理管理员和普通用户，并可删除非超级管理员账号。删除人员会删除其仅归属的模型、评测、报告和制品引用；平台治理资产转移给当前超级管理员，进行中的 Candidate 认领会先清理资料再释放。

## 9. 常见使用提醒

- 评估平台不可选：等待模型分析完成，并让管理员检查 Catalog、Binding、HostAgent、Worker、容量和 Runner 是否同时健康。
- 评估卡在执行中：进入 Flow 查看具体平台与阶段；不要反复创建重复任务。
- 没有报告/PDF：Flow 必须终态且当前账号有访问权限；报告只基于该 Flow 的冻结事实。
- 看不到其他用户的模型或报告：这是资源隔离的正常行为。需要共享时，由资源拥有者按系统共享流程授予授权。
- 不要在模型、评估、Candidate 或帮助文字中粘贴密码、Token、SSH 地址、宿主机路径或 Shell 命令。请由部署管理员在 Host 私有配置和固定 Runner 中维护这些信息。
