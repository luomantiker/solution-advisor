## 已落盘的实现与自动化验收

- 用户入口为平台无关的 `EvaluationFlow`。一次 Flow 冻结每个平台的 Catalog、Binding、Worker、
  Runner Release、镜像锁、规则、制品格式、Evidence 家族和解析器版本；用户请求不接受 Worker、
  镜像、命令、Docker、SSH、板端、路径或凭据。
- X5 固定为 `X5_COMPILE → REAL_BOARD_SMOKE`，只使用 `model.bin / x5_bin`、X5 Evidence 和 X5
  解析器；S100 固定为 `S100_COMPILE → S100_BOARD_PERF`，只使用 `.hbm / s100_hbm`、S100 Evidence
  和 `s100-hrt-profile-1.0`。后端拒绝跨 Flow、跨平台、跨 Worker 的制品/Evidence 引用。
- 用户详情页每 5 秒局部刷新非终态阶段；报告和 PDF 仅汇总实际选择平台，显示制品格式、固定 Runner、
  解析器、实测性能和未验证边界，不做未对齐条件下的 X5/S100 性能排名。
- 流程删除只能在全部内部阶段终态后进行，按 Flow 清理其内部任务、结果、Evidence、快照和仅被该
  Flow 引用的 Artifact；内部编译或板端阶段不能单独删除。
- 全量自动化回归：`uv run pytest -q` 为 **94 passed**，全局覆盖率 **80.67%**（门槛 80%）；涵盖
  X5/S100 Flow 创建与快照、S100 独立 Worker API 与 Evidence 白名单、`.hbm / s100_hbm` 唯一制品
  契约、错误身份/Binding/Runner/跨 Flow 引用拒绝、取消/超时/迟到回传幂等、Flow 部分成功汇总、
  Flow 删除、报告/PDF 和双平台容量调度。
- `tests/test_flow_parallel_capacity.py` 额外覆盖四个双平台 Flow：每个 Binding 的前三个编译阶段
  可分别占用三个槽位，第四个等待；同一 Binding 的板端阶段串行，X5 与 S100 两个不同 Binding 可
  并行，所有 Flow 均可独立生成有效 PDF。测试数据只使用临时产物并在测试结束后清理。
- `npm --prefix frontend run build`、`git diff --check`、`docker compose config`、
  `docker compose -f docker-compose.prod.yml config` 均已通过；生产近似 Compose 的 API、
  common-analyzer、Web、PostgreSQL、Redis、MinIO 容器均处于运行/健康状态。

## 普通用户浏览器首次实测（失败事实保留）

为避免以超级管理员 Session 冒充普通用户，本轮创建了一个本机一次性浏览器验收 USER，会话通过页面：

```text
本地账号登录 → 上传受控 ONNX → 等待 Model Profile → 创建 X5 + S100 Flow
```

实际创建的普通用户 Flow 为 `flow_691514fd966846dcae67a7e9026e1eb9`。两条编译阶段均成功，且
S100 编译已将唯一 `.hbm / s100_hbm`、SHA256、编译日志、Runner 结果和摘要以 MinIO Evidence 入库。
随后：

| 阶段 | 实际状态 | 真实原因 |
| --- | --- | --- |
| `X5_COMPILE` | 成功 | 受控 X5 Runner 已产生登记制品与 Evidence |
| `S100_COMPILE` | 成功 | 受控 S100 Runner 已产生唯一 `s100_hbm` 与 Evidence |
| `REAL_BOARD_SMOKE` | 失败 | `board_connection_or_preflight_failed` |
| `S100_BOARD_PERF` | 失败 | `s100_board_connection_or_preflight_failed` |

脱敏诊断表明：两份 Host 私有 board profile 所指 SSH TCP 端口均可连接，但使用 HostAgent 同一受控
`sshpass + StrictHostKeyChecking=yes + known_hosts` 方式的身份验证均失败。私有 Profile、Token、
口令、板端地址和路径均未写入本记录、数据库明文字段、页面或 Git。

因此该普通用户 Flow 真实汇总为“部分成功/失败”，没有生成可被宣称为成功的板端性能报告或 PDF。
现有管理员成功 Flow 的 PDF 不能替代这一项普通用户闭环；该失败 Flow 与其 Evidence 不删除、不改写。
