# 用户模型、评估历史与共享

普通用户的模型与评估默认相互隔离。上传的 ONNX 二进制按 SHA-256 做全局内容去重以节省存储，但每位上传者
都会得到独立的逻辑归属记录和评估历史；相同模型不会因此自动出现在其他普通用户的列表中。

## 用户评估工作台

登录后的左侧导航包含“评估工作台、上传模型、我的模型、我的报告”。普通用户只会看到自己
拥有或被明确共享的模型，以及自己创建或被明确共享的评估结果；平台治理、Worker、Binding、
Candidate 和管理员验证记录不会出现在这些页面中。

评估工作台展示真实的进行中 Flow、最近评估与报告入口。它只读取用户自己的 `EvaluationFlow`
摘要，不展示 Host、Worker、镜像、Runner 实例、板端地址或其他执行私有信息。

## 创建评估

创建评估采用三个步骤：

1. 选择已完成 ONNX 检测的模型；
2. 按平台类型选择可调度版本。同一平台类型只能选择一个版本，不同类型可组合选择；不可用
   平台会显示中文原因且不能提交；
3. 确认模型、平台和受控预设后创建一次 `EvaluationFlow`。

用户不会填写命令、Docker 参数、路径、凭据、Host、Worker 或 Runner。控制面会在创建时冻结
Catalog、规则、制品格式、Runner 和解析器版本，并在任一选中平台不可调度时整体拒绝创建，
不会生成半套评估。

## 查看结果和历史

1. 在“我的模型”打开模型，查看通用 ONNX 检测，并从“三步创建评估”发起真实 Flow。
2. Flow 详情以时间线显示各平台编译、自动板端性能阶段和中文状态；未结束的 Flow 每 5 秒局部刷新。
3. 详情页只列出本 Flow 的受控 Evidence/Artifact 下载和脱敏冻结快照。已结束 Flow 可查看网页报告、下载 PDF 或删除整次评估；删除只在全部内部阶段终态且权限满足时允许。
4. “我的报告”按已结束 Flow 汇总历史结果；模型详情也保留该模型下的 Flow/报告列表。不同平台的
   输入、线程、帧数或 Runtime 条件未对齐时，页面和 PDF 都不会作无条件性能排名。

## 共享规则

- 共享的单位是一条或多条同一模型下的已完成评估结果。由某条记录发起分享时，该记录默认选中，分享者可再勾选其他已完成记录；接收人总能在自己的模型列表看到模型名称、分享者和被分享的报告，不会获得未被选中的历史评估。
- 分享时可选择“同时附带 ONNX 模型文件”。选择后，接收人可下载模型、查看 Profile 并基于该模型创建自己的独立评估；未选择时，模型下载和新建评估均被禁用。
- 分享者可撤销某次评估分享；撤销后接收人立即不能再访问该报告。若该模型没有任何其他“含模型”分享，模型下载权限也随之移除。
- 分享接收人填本地用户名或公司 SSO Subject。系统不向普通用户提供全员目录，避免枚举其他账号。
- 每次共享与撤销均写入资源访问审计。

管理员和超级管理员按三角色治理职责可查看普通用户资源；普通用户之间不具有该跨用户访问权限。

## 客户交付报告与版本

已结束的 `EvaluationFlow` 可生成客户交付网页报告和 A4 PDF。报告严格只读取该 Flow 创建时冻结的模型/Profile 分析快照、平台快照，以及该 Flow 内部阶段的真实 Artifact/Evidence；不得混入 Candidate 接入验证、管理员测试、其他 Flow 或 DEMO 的事实。

报告固定为四章：多平台评估结论摘要、ONNX 模型检测概要、按平台拆分的适配与板端测试结果、后续优化建议；附录列出 Evidence、制品 SHA256、规则、Runner、Parser 与版本快照。性能只表达各自固定条件下的实测值；输出一致性、精度、稳定性、功耗和部署推荐没有独立证据时必须明确标记为“未执行/未验证”。

每个 Flow 的报告采用追加版本：首次查看生成 V1；用户点击“生成新报告版本”才创建 V2、V3……。每个版本冻结自己的报告快照，下载 PDF 时将 PDF Artifact 绑定到该版本；既有版本及 PDF 永不静默覆盖。历史 Flow 若缺少创建时模型快照，只能从仍可证明关联的 Profile/模型补录为“历史回填已验证”；无法证明时必须显示“历史快照不可用”，不得重新分析或猜测历史结论。删除整个终态 Flow 会一并清理该 Flow 专属报告版本/PDF，不会影响模型、Catalog 或其他 Flow。
